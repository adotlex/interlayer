# B1 — core: config, store, audit, retention, errors, PRIVACY.md

## What I built

`errors.py` roots everything at `InterlayerError`. `config.py` ships a frozen, validating
`Config` with the mandated defaults, TOML/YAML/env loading (unknown keys are an error, not a
shrug — a silently ignored `retian_emails` is a privacy failure that looks like a working
config) and a canonical-JSON `config_hash` that is stable across processes and
`PYTHONHASHSEED`. `store.py` is SQLite under the state root: member/target/edge columns are
generated from `ALL_FIELD_ALLOWLISTS` and re-checked against the live database at open time, so
PRIV-08 is enforced at runtime and not only in a test; `put_row` is the single choke point every
writer funnels through; provenance is mandatory rather than defaulted; email is written NULL
unless opted in; `prune_non_bridges`, `purge_person`, `purge_target`, `purge_all` and
SHA-256-hashed tombstones (so honouring erasure does not itself durably list erased slugs).
`audit.py` accepts exactly five keys and slug-shaped tokens, so there is no field to put a name
in. `retention.py` sweeps on startup; `startup()` makes "sweep first" a property of the code.
`PRIVACY.md` states the Art. 14 posture and says plainly that the household exemption probably
does not apply. 135 tests pass; ruff and mypy are clean on my files.

## Controls I could not fully satisfy

- **PRIV-15 is structurally, not semantically, enforced.** `action` and `adapter` must match
  `^[a-z][a-z0-9_.:-]{0,63}$`, which rejects every name with a space, capital, apostrophe or
  `@` — but a caller could still pass `adapter="griffin"`. Closing that needs a closed adapter
  vocabulary, which B4 owns. The record schema has no free-text field at all, which is the part
  I could guarantee.
- **PRIV-12 and PRIV-21 are half mine.** I return the surviving paths from `purge_all()` and
  ship `PRIVACY.md`; the non-zero exit and `interlayer privacy` are B5's.
- **PRIV-03 covers my layer only.** Report output paths are B5's.

## Needed in the frozen contract (orchestrator, please amend centrally)

1. **`ruff check src/interlayer/core/` cannot be made clean by me — all 11 errors are in
   `models.py` and `ids.py`.** They should be *suppressed*, not fixed: `UP042` would turn
   `class Firm(str, Enum)` into `StrEnum`, which changes `__str__` from `Firm.CITADEL` to
   `citadel` and would silently alter every f-string in the build; `RUF001` fires on the
   ambiguous characters in `ids.py` that the module exists to fold. Add to `pyproject.toml`:

   ```toml
   [tool.ruff.lint.per-file-ignores]
   # Frozen Wave 2 contract. UP042 would change Enum.__str__; RUF001 fires on the
   # very characters ids.py exists to normalise.
   "src/interlayer/core/models.py" = ["UP042", "RUF022"]
   "src/interlayer/core/ids.py" = ["RUF001", "UP032"]
   ```

2. **`Provenance.posture` is on no allowlist**, so a persisted record round-trips as
   `FIRST_PARTY_EXPORT` regardless of how it was collected. That weakens PRIV-04 after the fact:
   the store cannot say which posture produced a row. Suggest adding `posture` to
   `MEMBER_FIELD_ALLOWLIST`, `TARGET_FIELD_ALLOWLIST` and `EDGE_FIELD_ALLOWLIST`. I did not
   add the column, because that would breach PRIV-08 against the frozen constant.

3. **`Firm` has `citadel`; R5's registry entity id is `citadel_llc`.** I alias
   `citadel_llc`/`citadel-llc`/`citadel-securities`/`jane-street` in `store._FIRM_ALIASES` so
   `purge --target` accepts whatever the user has to hand, but B2's registry loader and my
   `Firm` values will need the same mapping. Better fixed once, in `models.Firm`.

4. **PRIV-07 and coverage are in tension.** `prune_non_bridges()` deletes edge-less *targets* as
   well as edge-less members, per the literal control — which destroys the coverage denominator
   and the next-harvest queue. **Compute `Coverage` and `NextTarget` before calling it.** If
   Wave 3 wants harvested-but-empty targets kept for `n_targets_harvested`, call
   `prune_non_bridges(observed_only=...)` is not enough and the control needs re-wording.

5. Minor: `enabled_adapters` is a `list[str]` inside a frozen dataclass, because PRIV-04's test
   is literally `default_config().enabled_adapters == ["first_party_export"]` and a tuple fails
   that. It is not defensively copied.

## API the other packages will want

```python
from interlayer.core.config import Config, default_config, load_config   # config.config_hash
from interlayer.core.retention import startup        # -> (Store, SweepResult); sweeps first
from interlayer.core.store import Store              # context manager

store.add_member(m) / add_members(ms) -> WriteResult   # False/suppressed => tombstoned
store.add_target(t) / add_targets(ts)
store.add_edge(e)   / add_edges(es)
store.members() / targets() / edges(observed_only=False) -> dataclasses with provenance
store.queue_review(CompanyMatch, provenance=..., normalised=..., member_count=...)
store.reviews(pending_only=True) / pending_review_count()      # PRIV-20 report count
store.prune_non_bridges() -> PruneResult                       # call AFTER coverage
store.purge_person(id_or_slug) / purge_target(entity_id) -> PurgeResult
store.purge_all() -> list[Path]                                # empty == success (PRIV-12)
store.path_for("derived", "x.json") -> Path                    # only safe way to name a file
store.audit.append_for(config, "export", adapter="none", count=n)
```

- Every `add_*` needs a `Provenance` (on the record or passed in) or it raises `StoreError`.
- `add_*` returns `False` when a tombstone suppresses the write — that is PRIV-13 working, not a
  bug. Check it rather than asserting a count.
- Slugs are normalised through `ids.normalize_slug` on write.
- Timestamps are stored as fixed-width UTC ISO-8601 so SQLite string ordering is chronological
  ordering; do not write `collected_at` by hand.
