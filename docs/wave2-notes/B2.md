## The one registry change I had to make

R5's registry names the hedge fund `citadel_llc`. `core.models.Firm` — frozen — has
`CITADEL = "citadel"`. Registry ids are the join to `Firm`, so I renamed the entity
`citadel_llc` → `citadel` in `data/targets.yaml` and in the expected-entity column of
`tests/fixtures/company_strings.yaml` (11 cases). **Nothing else changed**: no alias, regex,
threshold, discriminator or normalisation token. Both files carry a header comment recording
this, and `test_ingest_targets.py` asserts that an entity id which is not a `Firm` member is
rejected at load.

Two additive, non-semantic things also went into `targets.yaml`: the provenance header, and a
comment block reproducing R5's "Resolving the numeric company IDs locally" procedure at the
point of use, because `company_id: null` is the one field a user fills in by hand.

## Deviations from R5's spec text, and why

1. **`normalise_company` uses NFKD combining-mark folding, not `unidecode`.** R5 §A step 4
   specifies `unidecode` for companies. `unidecode` is not in the pinned dependency set, C2
   rejects it, and `core.ids.fold_accents` produces the same answer on every fixture case
   (`Jané Stréet` → `jane street`). Verified: 100/100 still holds. Adding `unidecode` would buy
   nothing and would put a transliterating library one import away from person names.
2. **No `jellyfish` phonetic key, no `nicknames` lexicon** in `person_match`. Neither is
   installed, both are Latin/Anglo-only, and R5 gates them behind an `is_latin_script` check
   for that reason. Cost is recall on `Smith`/`Smyth` and `bill`/`william`, not precision —
   those pairs simply do not surface as review candidates. If Wave 3 wants them, they need
   `jellyfish==1.2.1` and `nicknames==1.0.1` added centrally.
3. **`nameparser` title/suffix stripping** (R5 §C step 2) is covered by
   `core.ids._SUFFIX_TOKENS`, which already drops `jr`/`phd`/`cfa`/etc. No library needed.

## What I need from B1

Nothing blocking — everything below has a working local default, and ingest runs today.

1. **`core/errors.py`.** It did not exist when I started, so I did not import it. Every ingest
   exception derives from `interlayer.ingest.IngestError`, which derives from `ValueError`.
   When you add `core.errors.IngestError`, please make it a `ValueError` subclass and either
   alias ours to it or have ours inherit from it — a one-line edit to `ingest/__init__.py`
   that I am happy for you to make, or tell me and I will. Do **not** make it inherit from
   bare `Exception`: `except ValueError` around ingest is already in the tests.
2. **`retain_emails` is a parameter, not a config read.** `parse_connections_csv(...,
   retain_emails=False)` — PRIV-06 default. Pass `config.retain_emails` at the call site
   (B5's `ingest` command). `ingest` deliberately does not import `core.config`.
3. **State root.** `review.default_decisions_path()` resolves `$INTERLAYER_STATE_ROOT` then
   `~/.interlayer`, matching your `Config.state_root` default. If your key name or default
   differs, tell me and I will follow it; better still, B5 should pass an explicit path to
   `ReviewQueue.save()/load()` and the default never fires.
4. **The decision cache is YAML at `<root>/review_decisions.yaml`**, per R5, not a table in
   your SQLite store. If you would rather own it, `ReviewQueue` takes and returns
   `ReviewDecision` objects and its persistence is two methods — easy to swap.
5. **Audit.** `ReviewQueue.audit_event(action, key)` returns a name-free dict
   (`{action, key_hash, entity_id, pending}`) shaped for your JSONL writer. R5 requires cache
   hits to be logged so a wrong past decision stays traceable; ingest does not write the log
   itself.

## What B3 and B5 need to know

- **`needs_review` cannot reach the graph.** Use `company_match.is_admissible(match)` or
  `require_admissible(match)` (raises `NeedsReviewError`). `company_match.partition(matches)`
  splits three ways and exposes `.unadjudicated_count`.
- **`ReviewQueue.unadjudicated_count` is the company figure** that feeds
  `AnalysisResult.unadjudicated_count` and the report's review section (PRIV-20). Person
  review pairs are counted separately by `person_pending_count` — they never block an edge,
  they only suggest a merge.
- **`CompanyMatch.rule` names the rung that fired**, joined with the review reason when they
  differ: `exact_alias`, `anchored_prefix`, `fuzzy_token_sort`, `review_only_alias`,
  `negative_pattern`, `anchored_prefix/unexpected_tokens:technology`,
  `fuzzy_token_sort/fuzzy_anchor`, `ambiguous_entity:citadel|citadel_securities`,
  `cached_decision`, `empty`, `no_anchor_or_negated`, `below_floor`. Safe to render verbatim;
  it contains no personal data.
- **`CompanyMatcher.explain(raw)`** returns candidates, per-entity elimination reasons and the
  unexpected tokens — that is what a review UI should show.
- **Bare `Citadel` carries residual entity ambiguity** and is assigned to `citadel` because
  that is the hedge fund's page display name. Both Citadels share `group: citadel`; the report
  must footnote this (`registry.group_of(firm)`).
- **`Member.linkedin_slug` is mutable** (5 changes / 180 days, then the old URL 404s). Key
  persisted state on `person_match.person_id(...)`, never on the slug.

## Things a future editor will be tempted to undo, and must not

- **Do not reintroduce a threshold-based general matcher.** All eight rapidfuzz scorers were
  measured against 28 positives / 26 negatives and every one fails; `token_set_ratio` scores
  `Jane Street Capital LLC` and `Jane Street Entertainment` both at 100. `test_ingest_
  company_match.py` asserts those measurements directly so the reasoning survives.
- **Do not hand-edit the `normalisation` block** in `targets.yaml`. The 100/100 depends on it;
  `test_ingest_targets.py` pins both vocabulary sizes (43 legal suffixes, 101 modifiers).
- **Do not scope the unexpected-token vocabulary to the whole entity.** That bug scored
  `Citadel Capital` confident because `capital` appears in `Surveyor Capital`.
- **Do not hard-code `skiprows`.** `test_a_fixed_skiprows_3_would_have_corrupted_three_of_the_
  four_fixtures` is the standing negative control.
