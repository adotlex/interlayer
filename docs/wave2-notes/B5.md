# B5 notes — CLI, reporting, packaging, runbook

No amendment to the frozen contract is requested. `core/models.py` and `core/ids.py` were
sufficient as written; `AnalysisResult` carried everything the renderers needed.

## Integration contract the CLI calls

`cli.py` imports every sibling package **lazily, inside the command body**, so
`import interlayer.cli` and `interlayer --help` succeed with a half-built tree. The symbols it
calls are listed here so a signature change has one place to be checked. They match what the
other work packages shipped, and the CLI was verified end-to-end against them.

| Command | Component | Symbol called |
|---|---|---|
| all stateful commands | `core.config` | `load_config(overrides={"state_root": ...})`, falling back to a no-argument call |
| all stateful commands | `core.retention` | `startup(config) -> (Store, SweepResult)` |
| `ingest` | `ingest.connections_csv` | `parse_connections_csv(path, retain_emails=...)`, `.members`, `.warnings` |
| `ingest` | `core.store` | `add_members`, `counts` |
| `targets` | `ingest.targets` | `load_registry(path=None)`, `.entities`, `.id`, `.canonical`, `.firm` |
| `review` | `core.store` | `reviews(pending_only=...)`, `pending_review_count()` |
| `analyse` | `core.store` | `members()`, `targets()`, `edges()`, `pending_review_count()` |
| `analyse` | `graph` | `analyse(members, targets, edges, include_inferred=, unadjudicated_count=, ...)` |
| `purge` | `core.store` | `purge_all()`, `purge_person(id)`, `purge_target(id)` |
| `privacy` | — | reads `PRIVACY.md` from the repository root, `$INTERLAYER_PRIVACY_FILE` or `--path` |

Three failure modes are handled without a traceback, each with its own message:

- **absent** component — `_require` names the module and says which commands still work;
- **present but missing the symbol** — `_symbol` names the symbols it looked for;
- **raises** — `_guard` names the component and the exception.

Tuning parameters (`base_seed`, `gamma`, `n_runs`, `min_confidence`) are passed to
`graph.analyse` only if its signature accepts them, so a narrower engine still runs.

## Contract the report layer offers

`analyse` writes a versioned snapshot (`interlayer.analysis/v1`) to
`<state_root>/analysis.json` via `report.json_out.dump_result`. `report` and `next` read it with
`load_result`, so they depend on nothing but `core.models` and `report/` — a stored result stays
readable even if the graph engine cannot be imported. The snapshot round-trips exactly and
carries an optional `id -> display name` map, built in the CLI from the store because naming is
a presentation concern the analysis layer never needs.

Anything rendering an `AnalysisResult` should go through `report.render(fmt, result, ctx)` rather
than a renderer directly; that is what guarantees PRIV-17/18/19/20 uniformly across formats.
